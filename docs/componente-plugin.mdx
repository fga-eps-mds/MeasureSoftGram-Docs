# Plugin VS Code

O **Plugin** é uma extensão de **VS Code** que traz o painel de qualidade do
MeasureSoftGram para dentro do editor: a nota TSQMI e as características, dashboards
e a execução da qualidade sem sair do fluxo de trabalho. Repositório:
[MeasureSoftGram-Plugin](https://github.com/fga-eps-mds/MeasureSoftGram-Plugin).

## Como instalar e usar

1. **Instalação via arquivo `.vsix`:**
   Baixe o pacote da extensão na aba [Releases](https://github.com/fga-eps-mds/MeasureSoftGram-Plugin/releases) e execute no terminal:
   ```bash
   code --install-extension measuresoftgram-<versao>.vsix
   ```
   *Ou pela interface do VS Code:* Acesse **Extensions** (`Ctrl+Shift+X`) → menu `...` no topo → **Install from VSIX...**.
2. Clique no ícone do **MeasureSoftGram** na barra de atividades lateral, ou abra a paleta de comandos (`Ctrl+Shift+P`) e procure `MeasureSoftGram: Abrir Painel`.
3. Faça login com suas credenciais do MeasureSoftGram: o token fica protegido no Secret Storage nativo do VS Code.

## Pré-requisitos para desenvolvimento

- **Node.js 20** e **VS Code** (o `package.json` exige `engines.vscode ^1.120.0`).
- **Docker**, se você for rodar a Action localmente pelo plugin.

## Setup local

```bash
git clone https://github.com/fga-eps-mds/MeasureSoftGram-Plugin.git
cd MeasureSoftGram-Plugin
npm run install:all
```

Para desenvolver, abra o repositório no VS Code e use **F5** (Run Extension): o
editor compila e abre uma janela de desenvolvimento com o plugin carregado. Para trabalhar só na
interface (webview) isolada:

```bash
npm run start:webview
```

## Como testar e empacotar

```bash
npm run compile
npm run build:webview
npm run test:unit                                     # testes do Extension Host (Mocha)
cd webview-ui && npm run test:run && cd ..            # testes da webview React (Vitest)
npx --yes @vscode/vsce package --no-git-tag-version   # empacotar binário .vsix
```

## Release e Empacotamento de Produção

A extensão do MeasureSoftGram é empacotada no formato padrão `.vsix` e publicada nos releases oficiais do GitHub:

### 1. Gatilhos na branch de produção (`main`)
- **Tags Semânticas (`v*.*.*` ou `v*`):** Pushes de tags na `main` disparam automaticamente o workflow `.github/workflows/package.yml`.
- **Releases no GitHub:** Publicar uma nova release oficial na interface do GitHub também aciona a esteira de empacotamento.

### 2. Etapas da Esteira Automatizada
1. **Instalação Integral:** Resolução das dependências tanto do host Node.js quanto da interface React (`npm run install:all`).
2. **Compilação Dupla:** Compilação do código TypeScript da extensão (`npm run compile`) e do bundle de produção do frontend Vite (`npm run build:webview`).
3. **Validação de Testes:** Execução de 100% dos testes unitários da extensão e dos componentes de tela da webview.
4. **Empacotamento com `@vscode/vsce`:** Geração do binário `.vsix` contendo todos os assets e bundles compilados.
5. **Publicação nos Releases:** Upload automático do `.vsix` como asset da Release no GitHub via `softprops/action-gh-release` e como artefato para inspeção via `actions/upload-artifact`.

### 3. Como testar com segurança (Dry-Run)
Para verificar se o empacotamento e compilação estão íntegros sem gerar release pública:
1. Acesse a aba **Actions** no repositório.
2. Selecione o workflow **Package & Release Extension (.vsix)**.
3. Clique em **Run workflow**, selecione a branch e marque `dry_run: true`.
4. O workflow compilará a extensão, rodará os testes e gerará o `.vsix`, disponibilizando-o como artefato para download na própria execução, sem alterar os releases públicos.
